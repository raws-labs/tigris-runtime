# tigris-runtime

C runtime that loads `.tgrs` plans and executes them in caller-owned fast and slow arenas with no allocation during inference. Library builds as C11 with `-Wall -Wextra -Wpedantic -Werror -Wvla`; the POSIX example is held to C99. Public, github.com/raws-labs/tigris-runtime; also published as ESP-IDF component `raws-labs/tigris-runtime`.

## Build, test, run
- `cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure`: registers only self-contained tests (loader, executor, executor_rows, explicit_workspace_link, kernels_f32, kernels_s8, lz4, weight_arena, tile_padding, row_offset, tile_2d, accel_routing, cmsis_arena, avg_pool_s8).
- Fixture-driven binaries are built but not registered: `test_e2e`, `test_s8_e2e`, `test_plan_contract`, `test_yolo_s8`, `dump_plan`, `tigris_posix_example`. They need `.tgrs` plans and `.reference.bin` files in `test/fixtures/` (gitignored), generated by the compiler repo's `scripts/gen_fixtures.py`; the README's `tigris gen-fixtures` is not a real subcommand.
- `test/run_all.sh [models_dir]`: rebuilds, then checks that tiled s8 outputs are byte-identical to the untiled baseline; `models_dir` defaults to `../tigris-bench/models/output`.
- `scripts/local_ci.sh [--strict] [--build-cppcheck]`: the CI gates ctest does not cover: stack frames <= 1024 bytes (`-DTIGRIS_STACK_USAGE=ON`, `check_stack_usage.py`, `check_workspace_link.py`), a MISRA baseline against a pinned Cppcheck version (`scripts/static_analysis_baseline.json`), per-file coverage floors under a pinned gcc/gcov (`check_coverage.py`); the pinned versions live in `local_ci.sh`. A missing tool skips the gate loudly; `--strict` fails it; `TIGRIS_CPPCHECK=<bin>` skips the source build.
- CI also runs clang ASan/UBSan, a libFuzzer loader smoke (`test/fuzz_loader.c`, corpus from `test/make_fuzz_corpus.py`), an arm-none-eabi cross build (`-DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake -DCMAKE_C_FLAGS="-mcpu=cortex-m4 -mthumb"`), and `test/package_consumer` against a `cmake --install` prefix (`find_package(tigris_runtime 0.6 CONFIG)`, `tigris::runtime`).
- `tigris_contract_runner` and `tigris_contract_runner_rows` are host bridges driven by the compiler repo's cross-repo contract gate; not ctest cases. The `_rows` twins compile the sources with `TIGRIS_COUNT_KERNEL_ROWS` to prove line-buffered chains compute fewer rows.
- ESP-IDF example: `cd examples/esp32/getting-started && idf.py set-target esp32s3 && idf.py flash monitor`; ends with `SELF_CHECK: PASS` and `TIGRIS_DONE`. Its `main/idf_component.yml` uses `override_path` so it builds against the local checkout; `idf.py create-project-from-example "raws-labs/tigris-runtime:getting-started"` drops that and resolves the registry component.

## Layout
- `src/tigris_kernels.c` float32 reference, `tigris_kernels_s8.c` int8 reference, `tigris_kernels_esp_nn.c` and `tigris_kernels_cmsis_nn.c` adapters (empty translation units unless `TIGRIS_HAS_ESP_NN` / `TIGRIS_HAS_CMSIS_NN` is defined). `src/tigris_accel_policy.h` is the host-testable rule for native adapter vs `s8_ref` per op.
- `include/tigris.h`: the `TIGRIS_SCHEMA_VERSION*` macros define the accepted plan-schema range. `include/tigris_config.h`: `TIGRIS_MAX_*` table limits and `TIGRIS_ENABLE_DEFAULT_EXECUTOR_WORKSPACE`, all overridable; `stack_config_compile` keeps the reduced-limit build compiling.
- `test/schema_compat/`: one frozen plan per schema version. `test/cmsis_stub/`: declaration-only CMSIS-NN headers so the adapter compiles in native CI (`cmsis_adapter_compile`, `test_cmsis_arena`).
- `CONTRIBUTING.md` (Releasing), `idf_component.yml`, `.github/workflows/publish-component.yml`: ESP Component Registry publishing. Pushing a `v*` tag uploads the repo as the component; `idf_component.yml` `version` must equal the tag; needs the `IDF_COMPONENT_API_TOKEN` secret. The manifest ships only `examples/esp32/getting-started`.

## Gotchas
- Root `CMakeLists.txt` is dual-mode: when `idf_component_register` exists it registers the repo as an ESP-IDF component (with `TIGRIS_HAS_ESP_NN`, requires `esp-nn`) and returns; otherwise it is the host library. Install/export and tests are configured only when it is the top-level project.
- `-DTIGRIS_HAS_CMSIS_NN=ON` links a `cmsis-nn` target the runtime deliberately does not define; the embedding project supplies it (tigris-cortex-m does). CMSIS headers must be added as SYSTEM includes or `-Wpedantic -Werror` trips on them.
- Backend selection is by dispatcher: `tigris_dispatch_kernel` (float32), `_s8`, `_esp_nn`, `_cmsis_nn`. Accelerated adapters fall back to `s8_ref` only for explicitly supported variants; generate harnesses with `tigris codegen --backend ...` so the compiler validates the route.
- ESP-NN and CMSIS-NN need a prepare call after `tigris_mem_init()` and before `tigris_run()`. `tigris_esp_nn_prepare()` takes platform-managed workspace (PSRAM preferred) and `tigris_esp_nn_deinit()` frees it. `tigris_cmsis_nn_prepare()` carves scratch from the top of the fast arena and reduces `mem.fast_size`; size that arena with `tigris_cmsis_nn_fast_arena_required()` and call `tigris_cmsis_nn_deinit()` before changing arena or plan.
- `TIGRIS_TENSOR_ALIGN` (`tigris_mem.h`) auto-detects: SVE 64, aarch64/NEON/RVV 16, x86_64 32, Xtensa 8, Cortex-M with DSP 16, else 4; override with `-DTIGRIS_TENSOR_ALIGN=N`. Optimized Cortex-M builds require the plan base and tensors to satisfy it. The compiler's cost model aligns activations to 32 bytes, so it is conservative for every supported target.
- ESP-NN: `#include "sdkconfig.h"` must precede `<esp_nn.h>` or `CONFIG_NN_OPTIMIZED` is unset and the ANSI C kernels are chosen silently. Struct fields follow TFLM (`filter_dims.channels = 0`, `dilation = {0, 0}`). Depthwise output goes through a 16-byte-aligned bounce buffer because `ee.vst.128.xp` needs it and the arena may not provide it; FC input relies on `TIGRIS_TENSOR_ALIGN >= 8`; the scratch region gets 16 bytes of slack for ESP-NN's internal sub-allocation.
- ESP-NN `esp_nn_avg_pool_s8` cannot requantize, so `GlobalAveragePool` and pools with differing in/out quantization route to `s8_ref`. ESP-NN Conv/Depthwise encode unit dilation only; other dilations route to `s8_ref` (CMSIS-NN honors dilation).
- Arena model: fast arena is bump allocated, reset and compacted per stage; normal stages may spill to the slow arena; nothing falls back to the heap, the executor returns an error instead. `mem.fast_peak` is the observed high-water mark, not the scheduled minimum.
- `tigris_run()` uses one process-global workspace and is not re-entrant; use `tigris_run_with_workspace_buffer()` with `tigris_executor_workspace_required()` bytes for concurrent inference.
- The getting-started example needs an ESP32-S3 with PSRAM (skip tensors spill there); `sdkconfig.defaults.esp32s3` assumes octal PSRAM and 16 MB flash, `partitions.csv` embeds the plan in a 3 MB factory app, all watchdogs are off and the main task stack is 64 KB.
